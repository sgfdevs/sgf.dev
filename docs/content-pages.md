# Content pages

Four explicit Kit routes load published Umbraco `page` content through the native Delivery v2 item-by-path endpoint: `/about/`, `/about/code-of-conduct/`, `/about/sponsorship/`, `/discord`. They are not a catch-all. Groups, leadership, companies and jobs remain outside this layer.

Configure `CMS_INTERNAL_ORIGIN` as an HTTP(S) origin and `CMS_DELIVERY_API_KEY` privately on the Kit server. The latter corresponds to backend `Umbraco__CMS__DeliveryApi__ApiKey`, sent as the native `Api-Key` header documented in the exported OpenAPI. No default key is supplied. The frontend requires it even though the tracked backend still permits public published-content access. This layer does not change the backend's blank tracked key, public-access setting, preview gate, protected-member rules or disabled media/member authorization. Operators who require native API-key-only access must set `PublicAccess=false` separately. Never put the key in public environment variables.

The separate generated client permits only those four paths, a fixed metadata/block field selection and credential-free GETs. Redirects are disabled. It uses server fetch, not Kit's credential-forwarding event fetch. It never sends browser cookies, the member bridge secret, authorization, preview or start-item headers. Missing configuration returns 503. Missing/protected items return 404; other upstream failures and malformed data return safe 502 errors. Timeout/cancellation returns 503. There is no invented fallback body when CMS is unavailable.

Only the page name, title tag, description, approved OG image and two known block aliases enter PageData. IDs, raw properties, dates, culture dictionaries, block settings and unknown pickers never leave the server. Unsupported blocks or malformed content fail rather than masquerading as a complete page.

The installed Umbraco 18.2 XML API documentation for `MarkdownEditorValueConverter.ConvertIntermediateToDeliveryApiObject` specifies a Markdown string, unlike its Razor HTML conversion. A small standalone `marked` parser converts that string, then the existing maintained `sanitize-html` package sanitizes it. Native rich-text markup goes directly to the sanitizer. Rich-text embedded blocks are not supported by the reviewed page datatype and fail closed. No Markdown/HTML UI framework or custom CMS converter was added.

The sanitizer retains headings, lists, tables, text formatting and safe internal or HTTP(S) links. It removes scripts, event handlers, inline styles, forms and embeds. Images and OG images use the existing JPEG/PNG same-origin mapping. PDF links use the existing public document origin separately, never the image proxy. Relative legacy PDF paths map from `/media/{folder}/{file}.pdf` to `{MEDIA_SOURCE_PUBLIC_ORIGIN}/{folder}/{file}.pdf`; existing public HTTP(S) hrefs remain links. No document fetch or generic media proxy was added.

About retains the actual hard-coded Razor body, registration and Discord links, sponsorship/conduct cards and governance documents. It only renders after the matching CMS page loads. Other pages retain their name heading and ordered block layout within the existing shared shell/theme. Page metadata overrides shell defaults without duplicate description/OG tags; canonical origin continues to use the existing validated site-origin helper and a fixed content path.

Synthetic fixtures verify the mapper/transport behavior, not real published CMS content. The install-only schema export does not prove that these four pages are published, their editor values match the tracked datatype, or document/image URLs resolve. No production media or document fetch is part of this work.
